# CRM 项目风险地图

## 高风险区域

| 文件/区域 | 为什么是承重墙 | 主要调用方 | 替代方案 | 修改后回归 |
|---|---|---|---|---|
| `server/src/index.ts` | 暴露所有 API、维护种子数据和错误契约 | 前端 API 调用、API 测试 | 优先在适配层增加参数，不直接改变公共返回结构 | 健康检查、用户列表、创建、更新、停用、404/400 |
| `web/src/App.vue` | 承载列表、筛选、表单、详情和状态切换 | 浏览器用户流程 | 优先局部修改现有计算和事件，不重写页面 | 列表、搜索、角色/状态筛选、新增、编辑、详情、停用 |
| `docs/spec.md` | 定义页面、数据模型和接口契约 | 代码生成、测试、Figma 交付 | 先更新需求和 Spec，再改实现 | 追踪矩阵和 API 契约检查 |
| `tests/crm.spec.ts` | 守护核心用户管理行为 | Playwright 测试运行器 | 增加覆盖，不降低断言 | 完整 E2E |
| `server/src/api.test.ts` | 守护 API 状态码和基础契约 | API 测试命令 | 增加契约断言，不放宽状态码 | API 健康检查和错误响应 |

## 修改承重墙前四问

1. 为什么必须修改？
2. 有哪些调用方法和调用方？
3. 有没有不修改承重代码的替代方案？
4. 修改后哪些功能必须回归？

## 演示动作

让分析者先读取本文件并输出风险清单。只有回答四问并完成影响分析后，才允许实现者修改高风险文件。
