# CRM 用户管理需求

> 演示数据均为虚构数据，仅用于 Trae Code CN 产品培训。

## 背景与目标

企业 CRM 需要一个统一的用户管理中心，让管理员查看组织内成员、分配角色、维护状态，并能快速定位需要处理的账号。

## 用户角色

- **管理员**：查看、新建、编辑、停用用户，查看角色权限。
- **销售经理**：查看和编辑用户，不负责角色管理。
- **只读成员**：仅查看用户信息。

## 功能需求

| 编号 | 需求 | 验收条件 |
|---|---|---|
| CRM-001 | 查看用户列表 | 页面显示姓名、邮箱、角色、组织、状态、最近登录时间。 |
| CRM-002 | 搜索与筛选 | 支持按姓名/邮箱/组织关键词、角色和状态筛选；无结果显示空状态。 |
| CRM-003 | 新建用户 | 姓名、邮箱、角色、组织为必填；邮箱格式不合法时阻止提交并提示。 |
| CRM-004 | 编辑用户 | 可修改姓名、邮箱、角色和组织，保存后列表即时更新。 |
| CRM-005 | 用户详情 | 点击用户可查看完整详情，并从详情进入编辑。 |
| CRM-006 | 启用/停用 | 可切换用户状态，操作后显示反馈并更新状态标签。 |
| CRM-007 | 角色权限 | 可读取管理员、销售经理、只读成员对应的权限清单。 |
| CRM-008 | 健康检查 | API 提供健康检查接口，返回服务状态。 |

## 业务规则与异常

- 邮箱必须符合基础邮箱格式，不能提交空值。
- 停用用户保留历史数据，状态变为“停用”。
- 列表加载失败时展示演示模式提示和本地种子数据。
- 无匹配结果时不能误显示已有用户。
- API 找不到用户时返回 404；请求字段缺失时返回 400。

## 非目标

真实数据库、SSO、审计日志、批量导入、真实客户数据和生产权限接入不在本次演示范围内。
