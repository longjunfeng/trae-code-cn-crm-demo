# 影响分析模板：按角色筛选用户

> 分析阶段只读代码和文档，不修改实现。人工评审通过后才能进入实现会话。

## 1. 目标和非目标

- 目标：在用户列表中按角色筛选，并保持搜索、状态显示、详情和权限规则不变。
- 非目标：重构用户实体、修改登录权限、引入数据库、调整 Figma 视觉规范。

## 2. 入口和调用链

- 页面入口：`web/src/App.vue` 的角色筛选控件和 `filtered` 计算逻辑。
- API 入口：`GET /api/users?q=&role=`。
- 数据源：`server/src/index.ts` 的内存用户数组。
- 直接验证：`tests/crm.spec.ts` 的列表和搜索场景。
- 相关验证：`server/src/api.test.ts` 的 API 健康检查和错误响应。

## 3. 直接与间接影响

| 范围 | 影响 |
|---|---|
| 直接 | 角色下拉选项、查询参数、返回用户集合、空状态 |
| 间接 | 搜索组合、状态筛选、详情入口、停用按钮、角色展示 |
| 高风险 | 权限条件、数据隔离、未过滤数据回退、API 契约 |

## 4. 允许修改的文件

- `web/src/App.vue`：筛选交互和展示逻辑。
- `server/src/index.ts`：仅在需要时补充角色查询条件。
- `tests/crm.spec.ts`：新增角色筛选和组合筛选回归。
- `docs/test-report.md`：记录验证结果。

## 5. 禁止修改的范围

- 不修改用户实体字段和状态语义。
- 不修改公共权限规则和停用逻辑。
- 不修改 Figma 设计令牌。
- 不进行无关重构、统一命名或组件抽取。

## 6. 必须回归的测试

1. 当前功能：角色筛选、搜索与角色组合、无结果空状态。
2. 相关模块：列表加载、详情、编辑和停用。
3. 核心业务：API 健康检查、缺字段 400、用户不存在 404、数据隔离条件。

## 7. 替代方案

优先在现有筛选适配层增加条件；只有当服务端查询必须改变时才修改 API。若不需要服务端改变，应避免修改承重代码。

## 8. 评审结论

- 分析者：填写影响面、风险和测试范围。
- 讲师/产品：确认目标、非目标和允许文件。
- 实现者：只在评审通过后开始编码。
